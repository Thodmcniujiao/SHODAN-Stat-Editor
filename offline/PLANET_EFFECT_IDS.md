# 四位词条 ID 与实际效果定义

入口：**星球任务 → 星球词条**，分为“星球词条分配”和“词条 ID 定义”。目录来自官方公开 GET
`https://api.live.prod.thehelldiversgame.com/api/WarSeason/GalacticWarEffects`，
本次快照共 312 项，其中 290 项为四位 ID。目录按数值排序，上框输入即跳转，下框搜索当前目录的 ID、名称、载荷与关联本地定义。

## 给指定星球添加现有词条

1. 在“星球词条分配”左侧选择目标星球；可以搜索名称或输入星球编号跳转。当前 WarInfo 目录包含 273 个星球。
2. 点击“选择词条”，在目录中搜索、选择需要的词条，再点“添加本词条”。点击“目标星球／返回”可回到该星球的计划。也可以在星球页直接输入多个词条 ID，用逗号分隔。
3. 按需开启“同时添加已确认配对的图标”。只会从生效 ID 补图标；单独选图标不会自动追加生效 ID。
4. 开启“启用星球词条分配（总开关）”，按后文接入代理并启动游戏。无需点击“写入游戏”。页面的“上次代理处理状态”显示是否已取得实时目录、是否处理到战况以及追加数量。

例如 `1397` 是临时战备词条。给星球添加这条效果填 `1397`，而不是 `effectType` 的 `32`，也不是 `values` 中的资源引用 `3484474549`。添加既有词条不需要改其原始定义。

计划即时保存为便携的 `Data/planet_effects.json`，与定义覆盖、游戏文件参数缓存分开；清缓存和关闭编辑器都保留。可给多颗星球分别设置不同 ID、逐项移除或重置当前星球计划。移除只停止后续响应中由本方案追加的内容，服务器原有词条始终保留。

代理只对本机收到的 `/api/WarSeason/<warId>/Status` 中 `planetActiveEffects` 追加 `{index, galacticEffectId}`，按星球与 ID 去重，不修改服务器、归属、战役、任务或其他字段。目标必须在当前响应的星球列表中，词条必须在本次实时目录中，且类别、名称引用与选择时一致；任何目标或 ID 无效时整次保持原响应。代理异步公开 GET 取得实时目录，不携带游戏凭据；未取得目录、目录超过一小时或目录不兼容时停止追加。

本次验证了 273 个目录星球的响应分配、图标配对、去重、原内容保留及编辑器操作。**尚未游戏内联调，不能保证所有类型在每颗星球、每种任务中都会产生玩法效果。** 本功能也不解锁无法出击的星球。

## 原始定义字段是什么意思

| 字段 | 用途 |
| --- | --- |
| galacticEffectId | 用来给星球分配的词条编号，例如 1397。 |
| effectType | 效果类别，决定如何解释载荷；不是星球编号或要添加的词条编号。 |
| values | 随类别变化的实际载荷，可能包含资源引用、数量或倍率。 |
| valueTypes | 对应各载荷项的类型标记，不是组件 TypeID 的局部索引。 |
| nameHash、description…Hash | 名称和各类说明文字的引用，不负责给星球启用效果。 |
| flags | 原始位标志，各位具体用途尚未确认。 |
| gameplayEffectId32 | 原响应的内部标识，具体关联机制尚未确认。 |

“网络定义覆盖”两开关仅控制定义覆盖；“星球词条分配”有独立总开关。普通分配只需使用后者。

## 网络定义编辑

各 ID 展示并允许编辑完整的数值定义：`effectType`、`flags`、`gameplayEffectId32`、文案哈希、`valueTypes` 与 `values`。ID 本身保持不变。元数据为 uint32，载荷为有限 JSON 数值；不额外加滑块上限。编辑后立即原子保存至程序旁的 **Data/galactic_effect_overrides.json**，不依赖游戏参数缓存、预设或“写入游戏”。R 恢复该字段，页面重置清除该 ID 的计划。

默认关闭定义覆盖。要覆盖一项，需要开启“覆盖本词条 ID”和“启用网络定义覆盖（总开关）”，并让游戏的定义请求通过附带插件。修改 1202 的载荷不会自动修改 1203，也不会给任何星球分配 1202。要添加到星球，使用独立的“星球词条分配”。

### 内置代理接入

完整构建已经内置官方 mitmdump 12.3.1 和独立运行环境，无需安装 Python 或配置 PATH。启动、停止均在“星球词条分配”页完成。

1. 点击“启动代理”，等待“本机代理服务”显示正在运行。
2. 首次使用点击“信任本机 CA”。只把本程序现场生成的 CA 加入当前用户根证书库，不修改计算机级证书库、系统代理或 hosts。CA 私钥保留在本程序的 `Data/WarProxy`，不会随公开压缩包分发。
3. 右下角设置的“启动时自动修复 Steam 接入”默认开启。修改器加载配置后自动检查当前账户的 Helldivers 2 启动选项；路径正确时不重复写入。需要首次配置或更换旧路径时，Steam 已退出则直接修复，Steam 运行中则等待退出后自动处理。也可在本页点击“重启 Steam 并修复”，请求正常退出并在处理后重开；游戏运行时拒绝该操作，超时不会强制结束 Steam。

   “立即修复接入”可手动触发同一流程。“恢复并关闭自动修复”会移除本程序管理的桥接，保留用户后续参数，并关闭自动修复以免再次添加。目标选项及应用记录保存在 `Data/SteamLaunchOptions/<account>.json`，不备份整个 Steam 配置。首次接管已有桥接时，恢复操作保留其后的已知参数。

   手动接入仍可用：点击“复制启动选项”，把它放在 Steam 的 Helldivers 2 启动选项中，并在后面保留已有参数。例如：

   ```text
   "C:\实际路径\SHODAN Stat Editor Offline\app\network\steam_bridge.exe" %command% /--use-d3d11
   ```

   接入检查显示“已接入当前构建”后，再启动游戏。移到新文件夹后，自动修复会检测并替换已记录或能核对执行文件的旧桥接。其他包装器、损坏配置或重复目标键不会被覆盖，页面显示原因。
4. 开启星球分配总开关，点击编辑器的“启动游戏”。编辑器会先准备代理、等待就绪，再交给 Steam；如果 Steam 尚未配置或本机 CA 未信任，会明确提示，不会声称已成功接入。
5. 右下角“设置”提供“关闭修改器时停止代理”，默认关闭：退出窗口后代理继续服务。开启时退出窗口会停止代理，正在使用该代理的游戏连接也会断开。使用结束后也可点击“停止代理”。删除 Steam 中的桥接部分即可恢复普通启动，保留自己原来的参数。

本页属于**网络层劫持**：本机 HTTPS 代理改写客户端收到的战况响应；不是把词条写入本地游戏文件，也不是修改服务器保存的星球状态。

原生桥接只给游戏子进程设置代理环境变量，保留原始命令行和工作目录；登录和反作弊域名加入绕过列表。只有活跃进程、创建时间、路径、有效心跳及 CA 信任均符合时才接入，过期会话不会用于新的游戏启动。两个方案总开关均关闭时按普通方式启动。

代理证书、私钥、心跳、原生桥接会话文件和处理状态全部位于 `Data/WarProxy`。不要把整个个人 Data 放进公开发布包。依赖来源及校验记录在 `app/network/runtime.json`，许可在 `licenses/mitmproxy.txt`。代理只监听本机地址 `127.0.0.1:8847`。Windows 吊销检查所需的 CRL 由临时的本机端口提供，只响应 `/ca.crl`；API 会话证书包含该地址。停止代理也会关闭 CRL 服务，不需要关闭 TLS 或吊销验证。

已验证默认 Windows Schannel 的 HTTPS 请求、证书链、吊销检查和官方目录；当前游戏已通过握手并取得战况，代理完成所选词条追加。战况改写还使用隔离响应验证原字段保留；未向服务器发送修改请求。游戏局内实际效果尚未实测。`proxy_health.json` 只保存游戏 API 的连接计数、响应状态及固定错误分类，不保存原始请求、凭据或 TLS 错误文本。

插件只处理目标官方主机、GET、200 成功响应的 `GalacticWarEffects` 和上述 `Status`。WarInfo、登录、请求体保持原样。定义覆盖只有在实时响应中唯一存在且完整原定义与保存基线相同的 ID 才能套用；更新后定义变动、缺失 ID、重复 ID、非法字段、损坏计划、304 响应均不套用。无修改时保留响应原字节。

### 自动接入实现与后续更新计划

目标：更新后仍从同一个快捷方式启动，用户不用再去 Steam 手动填写或更换桥接路径。

1. 使用固定安装目录和固定 `steam_bridge.exe` 路径，构建时间只写进版本信息，用户版本不再使用时间戳目录作为安装位置。更新保留 `Data`、`Presets`、`Names`，包括本机 CA 私钥和词条方案。
2. 修改器“启动游戏”先检查代理、证书和 Steam 接入；代理缺失就启动并等待就绪。自动接入负责为当前 Steam 账户的 553850 保留原参数、备份原值、加入或修复唯一的桥接前缀，不要求用户粘贴启动选项。
3. 已实现：Steam 已运行时不直接改写其正在管理的配置文件。自动配置安排在 Steam 正常退出后，校验目标账户和原值未变化，再原子写入；用户主动点击重启按钮时才自动重新启动 Steam。不强行结束 Steam，不覆盖第三方启动器，支持恢复原始启动选项。
4. 保留 Steam 正常启动链路，由原生桥接只向游戏子进程传入代理环境。给 `steam://` URL 附加文本不等于传递进程环境；在 Steam 已运行时，只设置修改器进程的环境也不能保证游戏收到代理。直接启动游戏的替代方案须另外通过 Steam 重启转交、登录及反作弊兼容测试，不能先作为默认路径。
5. 更新器改为本 fork 的发布源，下载后核对文件清单和 SHA256；游戏运行时延后安装。安装前停止本程序代理、等待退出、暂存新文件、失败回滚，成功后重启修改器，按原状态决定是否恢复代理。保留现有 CA，无需每次更新重新信任。

自动配置已覆盖：Steam 已开／未开、既有参数、空选项、缺键／缺游戏条目、重复键、中文／空格路径、旧构建迁移、重复启动、恢复、账户／文件并发变化及失败保留。原生重启流程在隔离控制器中验证正常等待、超时、游戏运行拦截和重新打开。固定目录部署和新版更新器仍属于后续计划。

每次启动的自动修复按以下边界实现：

- 独立 `steam_launch_options.lua` 提供检查、修复、恢复三个入口，`steam_integration.lua` 负责 Windows 原生接入。加载用户配置后检查当前 Steam 账户的 `UserLocalConfigStore/Software/Valve/Steam/apps/553850/LaunchOptions`，不遍历或修改其他账号和游戏。Steam 未运行且无活动账户时，仅采用唯一的最近登录账户，不能确定则不写入。
- 使用保留原文字节位置的 KeyValues 解析器，处理大小写、转义、注释和嵌套；只替换目标字符串，不用全文件正则替换或重新格式化。重复键、损坏结构和不明包装器不自动覆盖。
- 已正确配置时不写文件。路径变更时只替换已确认属于本程序的旧桥接前缀；完整保留其他参数，避免反复叠加桥接和 `%command%`。备份仅保存目标游戏的原始选项和本程序应用记录，不复制整个可能含账号数据的 Steam 配置。
- Steam 运行时若需要修复，状态为“等待 Steam 退出后自动修复”；不能把磁盘写入等同于客户端已经采用。可提供“正常重启 Steam 并修复”按钮，在用户点击且游戏未运行时执行；不强行结束 Steam。
- Steam 完全退出后重新读取最新文件，确认账号、旧值和文件未变化，写同目录临时文件；原生验证锁释放后再次检查，再原子替换并回读验证。失败清理临时文件并保留原值，界面显示具体状态。客户端再次启动后重新检查当前账号。
- 设置增加“启动时自动修复 Steam 接入”、修复及恢复按钮，本页另提供正常重启按钮。关闭自动修复不擅自清除已配置的参数；恢复时只移除本程序管理的前缀，不覆盖用户后续新增参数。
- 固定目录更新后桥接路径不变，后续启动通常只做检查；解压到新路径或切换账号才需要重新配置。Steam 运行状态、并发写入、配置缺键、中文／空格路径、重复启动、原参数保留和失败恢复均需隔离测试，再进行真实客户端验证。


## 关联的本地定义

- type 71：按 `values[0]` 匹配 `GalacticPresenceSettings.debug_name` 的 Murmur64 高 32 位。本次 76 个定义中有 71 个唯一匹配；其余 5 个不猜测。关联入口展示该记录的各参数组，点击后使用原页面和原字段，避免另存一份参数或混淆归属。
- type 94：1345、1346、1350 分别关联本地 Modifier ID `CDD51BC6`、`4DD68526`、`2A83FD6B`，可以打开并编辑真实的实体差异参数。其余 15 个旧 Modifier 定义仍保留在“星球效果修饰”。
- 本地定义的修改仍由“写入游戏”安装。修改图标／表现的本地参数，不等同于修改其配对生效 ID 的网络载荷。

## 数据来源与更新

- 官方完整响应的抓取 UTC 时间及 SHA256 包含在 `app/galactic_effect_data.lua`。
- 名称、文案及配对研究参考 [127MU/SHODAN-Stat-Editor](https://github.com/127MU/SHODAN-Stat-Editor/tree/26aed0ef664d9b21718b36f15210be0615f89165)，GPL-3.0。参考名称须同时匹配 ID、effectType 和 nameHash；名称不作为实际机制的证明。
- 本地资源匹配使用当前安装的游戏文件；英文文案来自 shalzuth/HelldiversData，遵循随包参考资料许可。
- 开发者用 `tools/update_galactic_effects.py` 重新抓取目录，或 `--input` 指定离线响应。该工具不会写入服务器。更新目录后，已保存但基线不符的计划会显示过期，需重置并按新定义重新编辑。
- 星球索引用 `tools/update_planet_effect_catalog.py` 从公开 WarInfo 更新；显示名称须通过设置哈希匹配已有星球资料，不能把本地配置记录序号当成网络星球编号。
