# 实体哈希分组与策划名

实体路径哈希是静态全局标识。实体组件列表使用同一份 `EntityNames` 文件夹：一个 JSON 是一个实体组，组内每项有 `hash` 和 `name`。列表中的分类直接来自这些组文件。

名称文件夹位于编辑器数据目录，通常为 `%LOCALAPPDATA%\SHODAN\StatEditor\EntityNames`；以界面“打开JSON文件夹”打开的位置为准。便携版优先读取 exe 旁边的 `Names\EntityNames`（随包分发）；该文件夹不存在时才回退到 `%LOCALAPPDATA%`。

## 操作

- 上方输入框接受十进制、`0x` 十六进制或无前缀十六进制哈希，输入时自动跳转，无需回车。64 位哈希始终精确处理。
- 下方搜索跨所有实体组匹配策划名、十进制哈希、十六进制哈希、原始名称和路径。搜索时也会找到没有当前组件的实体；这些实体仍为只读占位页。
- 不搜索时，分类和“显示无本组件的实体”继续控制列表范围。跳转会自动使目标可见。
- “重载JSON”应用文件夹中的全部组文件；“打开JSON文件夹”就在它右边。
- JSON 错误或同一实体出现在多个组时，提示错误并保留上次有效名称。移动分组时，请将条目从原组移至新组。

## 每组 JSON 示例

例如 `虫族.json`：

```json
{
  "version": 1,
  "id": "terminids",
  "group": "虫族",
  "order": 10,
  "entities": [
    {"hash": "0xF79CD8BB654397DF", "name": "我的阿尔法指挥官"},
    {"hash": "9007199254740993", "name": "十进制哈希示例"}
  ]
}
```

`group` 可省略，此时使用文件名；也可以像 `name` 一样使用语言映射，例如 `{"en":"Bugs","zh-Hans":"虫族"}`。`id` 可省略，编辑器会从文件名生成稳定分类标识。`order` 控制分类排序。新增一个 JSON，点击重载即可新增分组。

`hash` 请用字符串：纯数字按十进制读取；十六进制推荐始终加 `0x`，避免纯数字的十六进制哈希与十进制混淆。上方跳转框对有歧义的输入先匹配十进制，再匹配十六进制。上方输入不做模糊匹配，只有完整匹配的实体才会跳转。

独立场景 Unit 条目保留 `"kind":"unit"`；普通 ECS 实体的 `kind` 为 `entity`，可省略。组件继续归实际实体所有，名称和分组不会改变组件归属。

## 迁移与未分类

首次使用时，编辑器将原 `entity_catalog.json` 的分类规则和名称展开成各个组 JSON；原文件保留。旧 `record_names.json` / `.txt` 中的长实体哈希策划名也导入实体组。迁移完成后，请编辑新文件夹中的 JSON。便携版存在 exe 旁的 `Names\EntityNames` 时直接读取该文件夹，不会把 app data 的旧文件导入包内。

`未分类.json` 使用固定 `id: "other"`。尚未分类的实体，以及游戏更新中新发现的哈希，写入这里。将其条目移到其他组文件即可分类。加载不会覆盖已有组的策划名。

编辑器继续生成数据目录中的 `entity_catalog.index.json` 全量索引供外部工具查询；索引不是名称编辑入口。发布目录的 `ENTITY_CATALOG_SCHEMA.json` 描述新的组文件格式。

名称与分组仅影响显示和检索，不修改游戏资源哈希、TypeID、组件数值或存档。
