# 敌人设置 → 刷怪编辑器

原来的“拉烟编辑器”占位改为“刷怪编辑器”，用来编辑敌人生成所用组件的完整字段（`offline/spawn_components.lua`）。

## 敌人生成页三组参数的来源

“敌人生成”页虫族、机器人、光能者三页中的 13 行，都来自 HiveMindComponentData（敌人调度，1084 字节）。这个组件每种任务一条记录，+0 是阵营。每行按阵营同时缩放该阵营所有记录中的字段：

| 组 | 行 | 字段（偏移） |
| --- | --- | --- |
| 增援 | 增援（信号弹、虫潮、空投） | wild_encounters_enabled（+1077） |
| 增援 | 增援规模 / 增援频率 | 遭遇点数系数 / 遭遇冷却速率系数的 4 个玩家人数倍率（+316 / +376） |
| 增援 | 敌人数量上限 | encounter_enemy_cap_multiplier（+128） |
| 巡逻 | 巡逻频率 / 同时巡逻数 | 巡逻生成冷却速率 / 巡逻数量上限系数（+496 / +436） |
| 巡逻 | 修正巡逻频率 / 规模 | 游荡者波次冷却 / 最大单位数倍率（+976 / +1036） |
| 前哨与生成点 | 前哨驻军规模 | 守卫部队成员数上限系数（+856） |
| 前哨与生成点 | 构筑者 / 虫洞队列、批量、补充速度、释放速度 | 生成点队列上限、生成数量、生产冷却、生成冷却系数（+556 / +676 / +616 / +796） |

“所有阵营”页的 4 行（巡逻/增援频率下限、SEAF 增援/波次冷却）来自 SeafObjectivesComponentData（96 字节，游戏中只有一条记录）。

## 刷怪编辑器的分页

| 按钮 | 组件 | 字段 | 记录 |
| --- | --- | ---: | ---: |
| 敌人调度（HiveMind） | HiveMindComponentData | 277 | 19 |
| SEAF 目标（所有阵营） | SeafObjectivesComponentData | 24 | 1 |
| 小队哈希队列 | AiSquadComponentData | 21 | 21 |
| 生成器队列 | AiSpawnerComponentData | 54 | 33 |

- **敌人调度：**
  - 这是敌人调度组件唯一的完整编辑位置（“星球任务 › 任务编辑”中原来的敌人调度页已移除）；字段与敌人生成页的倍率行共用。
  - 这里按敌人生成页的分组排列：增援（所有 encounter 相关）、巡逻（patrol 与游荡者）、前哨与生成点（spawner、守卫部队），然后是任务进度与时间、阵营与其他字段。
  - 被敌人生成某一行缩放的字段，提示中写明是哪一行。
  - 页名按记录的阵营和任务时间限制取，例如“敌人调度：虫族 · 40 分钟任务 · D337A7BF”。
- **SEAF 目标：**
  - 布局来自游戏类型库：5 个计数、5 个数值、2 个计数、6 组“2 个浮点数”的数组。
  - 公开的 dump 和 2024 年结构都没有这个组件。后 12 个浮点数沿用 FileDiver 的命名（SEAF 增援冷却、SEAF 波次冷却、巡逻/增援频率下限），前 12 个显示为未命名。

两个组件的布局都已用当前游戏数据核对：
- HiveMind 19 条记录、SeafObjectives 1 条记录，都能按布局读出全部字段；
- 与游戏类型库一致。

“敌人生成”页本身不变，仍按阵营统一调整倍率。

## 小队哈希队列

当前 `AiSquadComponent` 记录长 112 字节，成员表在 +0x10，固定 6 个槽，每槽 16 字节：

| 槽内偏移 | 字段 | 类型 | 编辑 |
| --- | --- | --- | --- |
| +0 | member_path | uint64 | 怪物/成员实体哈希，支持完整十进制或 `0x` 十六进制 |
| +8 | amount | uint32 | 此种成员的数量 |
| +12 | node | uint32 | 载具挂点名称 ID |

21 条模板共 126 个槽位，空槽同样可修改。填写一个空槽时同时设置实体哈希和数量；清空时两者均设为 0。界面显示已知成员名称，名称依据实体哈希匹配本地 RawData；不依赖可变的枚举行号。队列名称标注“原模板”，修改成员后应以下方各槽实际值为准。

+0 是退出幽灵模式补员开关，+8 是小队类型；+4 浮点数的含义尚未完全确认（数值与旧结构的凝聚倍率一致），保留未知字段标记。全部原生字段、嵌套成员的大小和存储类型均核对后才开放编辑。

这些是磁盘上的**固定小队组成模板**，不是内存里正在执行的刷怪队列。不能据此断言所有普通巡逻、虫潮或空投都会采用其中某条模板；具体调用和动态成员抽选仍由任务/游戏逻辑决定。HiveMind 频率和规模设置继续独立编辑。

## 生成器生产队列

当前 `AiSpawnerComponent` 长 196 字节，33 条记录，包括虫洞、构筑者、营地传送门等：

- +0/+4：成员名称 ID 与备用成员名称 ID。这是敌人配置中的 **32 位成员标识**，不是 64 位实体哈希，不应直接粘贴怪物实体哈希到这里。
- +136：等待生成的怪物队列上限；+140/+144：每批数量与最低数量。
- +148/+152/+156：生产补充冷却、批次冷却、批内逐个生成间隔；+160：随机变化比例。
- +36：4 条生成通道，每条 20 字节，包含动作 ID、挂点名称 ID 和绑定开关。
- 其余动作、音效、开关及未确认字段均按实际布局显示。

此组件表结尾有 4 字节填充，解析时明确处理，不把填充当成新记录。

## 分类、保存和验证

小队和生成器按原始成员/实体阵营分类；HiveMind 也补上了阵营分类，选择“虫族”不再漏掉这类记录。名称文件或用户 JSON 的显式分类仍优先。

哈希用两段 uint32 保存和写入，不经过不精确的浮点整数转换；封装文件时不会拿成员哈希或 ID 的位模式做浮点校正。沿用现有预设、保存、重置及写入游戏流程。

`tests/test_spawn_queues.lua` 使用当前游戏只读数据和隔离配置，检查 21/33 条记录、126 个槽位、嵌套布局和存储类型拒绝、阵营筛选、十六进制输入、相邻字节保持、预设读回、认证封装重读和真实界面绘制。尚未验证实际运行任务中的全部巡逻/增援调用路径。

## 重新生成队列组件定义

`tools/component_gen/gen_spawn_queues.py` 与其他组件生成器共用 `COMPONENT_GEN_WORK`（含原始明文 `entities.bin`、`typelib.bin`）和 `RAWDATA`（RawData 仓库根目录）。生成器读取当前结构布局、固定成员表、阵营和哈希名称，生成 `offline/spawn_queue_components.lua`。已验证从本次原始数据重新生成得到的文件与测试版本完全一致。
