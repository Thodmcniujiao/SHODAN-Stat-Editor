# 实体拆毁扩展版

此本地版本在 SHODAN Stat Editor Offline 中新增“实体拆毁”入口。它按当前游戏文件扫描 ECS 实体和没有 ECS 映射的场景 Unit，对已有有效拆毁配置提供独立的任意整数阈值覆盖。

原游戏 build 26088801 的离线夹具识别到 3252 个目标，其中 1788 个具有可编辑的拆毁阶段。缺少映射、没有有效阶段或无法安全分离的目标，在“全部目标”中显示原因。该功能不会仅凭 Health 字段把一个没有拆毁机制的对象认定为可拆毁。

## 使用

1. 启动此目录中的 `SHODAN Stat Editor Offline.exe`。
2. 点击顶部“实体拆毁”。按名称、资源路径或哈希搜索；可以切换全部、可编辑、已修改列表。
3. 点击某条破坏记录的阈值，输入 `0` 至 `4294967295` 的整数，按 Enter 保存。直击没有独立配置时显示继承关系，输入后创建独立直击覆盖。
4. 关闭游戏，点击原有“安装到游戏”。需要克隆 Unit 时，会先导出相关资源并更新 package 依赖，再准备、验证并安装文件。
5. 重新进入游戏并重新生成目标。恢复此项或此实体后，再次安装会撤销对应覆盖。

“恢复游戏文件”同时恢复数据表并移除本编辑器创建且仍符合所有权记录的资源补丁。外部修改过的文件会被保护并报告，安装失败会尝试恢复安装前的数据表与资源补丁。

## 与原 Sentry 页面统一

原 Stat Editor 的 SENTRY / Deployer 拆毁数值与 Entity Demolition 页共用 `entity_demolition.txt`。在任一页修改、恢复或载入预设，另一页直接读取同一份实体设置；原页不再选择共享模板引用，也不会同时改动 Health 的死亡破坏类型。两页都支持 `0` 至 `4294967295` 的整数，并遵守 Settings 的 Changes 开关。安装只使用这份统一设置生成实体独立覆盖。

首次启动会迁移原 `config.txt` 内能对应到这些实体的旧拆毁修改。若同一条记录已有 Entity Demolition 覆盖，保留该覆盖；否则导入旧值。比如旧 Sentry 写 10、实体页写 20，会统一为 20。迁移成功后从 `config.txt` 移除重复的拆毁项，其他参数保留。两份原文件和逐项迁移说明备份在 `%LOCALAPPDATA%\SHODAN\StatEditor\demolition-migration-backups\` 的时间戳子目录。

原页的修改标记、统计、实体恢复、全局恢复和武器 / 整体预设都通过统一设置处理。直击仍可独立覆盖；清除直击覆盖后，两页都显示继承普通阈值。切换顶部页面或点击安装时会先提交当前输入；无效输入会阻止切换或安装，避免显示值与安装值不一致。

## 破坏记录（旧界面称 Stage）

“记录 1 / 2 / 3”对应 DestructionSettings 内三条破坏事件配置的数组槽位 `0 / 1 / 2`。这只是配置位置编号；现有证据不能证明它们代表三段血条或必定按顺序触发。每条可以有自己的模板、阈值和效果。没有有效阈值配置的项不显示，因此可能只出现记录 1 和记录 3。

同一条记录的“普通命中”和“直击覆盖”是两种配置路径，不是两个阶段。直击未指定独立模板时，界面显示其继承的普通阈值；输入直击值会创建该记录的独立覆盖。修改前先查看实体实际有哪些有效记录，不应只凭编号认定某一条是整实体死亡阈值。

界面修订：搜索框具有焦点边框及光标，支持名称、路径和哈希；搜索框内按 Enter 保留搜索，Ctrl+F 返回搜索。按钮文字改用字体实际度量居中，数值框和按钮均有边框，修复文字和点击区域错位。切换到拆毁页时释放旧编辑页的游戏输入拦截。

## 隔离方式

- 原有全局 DestructionTemplates 记录保持原值和原始字节。
- 每个覆盖分配新的私有模板和 DestructionSettings。原始阶段、效果及其他字段保留。
- ECS 实体得到确定的 Unit 资源别名及对应资源克隆；只有该实体的 UnitComponent.unit_path 改为别名。共用同一模型的其他实体继续引用原资源。
- 相关 package 会保留原依赖，并追加克隆 Unit。资源补丁使用未被其他工具占用的编号，或更新本编辑器拥有的文件。
- 场景 Unit 目标以其 Unit 资源为粒度，独立覆盖该资源的配置。

## 验证状态

用户已确认先前普通加特林血量 999999、共享模板阈值 999 的修改在游戏中生效。

本次新增的独立实体方案已通过批量隔离、共享模板不变、序列化重读、哈希保持、封装认证重读、真实加特林资源导出及 package 依赖修改、安装失败回滚与界面模型测试。新增模板编号和 Unit 别名的完整游戏内加载及战斗效果仍需实机验证，不能将已有共享模板测试当作这一新方案的实机证明。

如果此前对共享模板做过 999 试验，编辑器读取的基线仍可能是 999。此扩展会保留此前已存在的修改。为了清楚观察隔离效果，可以先恢复那次试验的备份，再给单一实体设置新值。

## 配置和依赖

实体拆毁设置自动保存在 `%LOCALAPPDATA%\SHODAN\StatEditor\entity_demolition.txt`，关闭重开会恢复。资源所有权记录位于同目录的 `entity_assets_installed.txt`；保留该目录与 originals 备份以便恢复。

ECS 实体独立覆盖读取 Unit 与 package 时使用编辑器自带的归档读取层（`offline/archives.lua`：DSAR 分块 bundles 与独立归档，索引按游戏版本缓存），不再需要 Filediver CLI。原生读取失败时，若找到 Filediver（`Downloads\Compressed\filediver-cli\filediver.exe`、环境变量 `SHODAN_FILEDIVER`、程序旁 `tools\filediver.exe`，或上述配置目录中的 `filediver path.txt`，只放可执行文件完整路径）才回退使用它。

此版本保留原程序的统计编辑和敌人编辑功能。为保护本地扩展，上游自动更新检查在此构建中关闭；合并上游版本后应重新构建本地扩展。

## 源码与测试

- `offline/demolition.lua`：类型库、目标目录、私有模板、独立映射及表生成。
- `offline/unit_aliases.lua`：原生读取（`prepare_native`，Filediver 仅兜底）、Unit 克隆、package 依赖与资源归档。
- `offline/archives.lua`：游戏归档只读层（bundles.nxa 列表、DSAR/LZ4 分块、文件目录、按类型建索引）。
- `offline/demolition_panel.lua`：界面、搜索、整数校验、自动保存与恢复。
- `offline/demolition_bridge.lua`：原页面与实体页的统一字段、旧配置迁移及备份。
- `offline/entity_assets.lua`：资源补丁所有权与回滚。
- `offline/host.lua` 与 `offline/hostdata.lua`：安装、恢复及哈希校正的集成。
- `tests/`：使用项目 LuaJIT DLL 的离线测试；原游戏夹具通过路径传入，不打入发布包。

资源名称索引来自 Filediver 公开哈希列表。归档格式依据 [Filediver](https://github.com/xypwn/filediver) 的公开定义。上游编辑器采用 GPL 3 许可；本地扩展沿用该许可。
