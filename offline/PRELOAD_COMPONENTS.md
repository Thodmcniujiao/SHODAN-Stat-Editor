# 预载设置与额外资源包

入口：杂项与设置 → 预载设置。目录基线为本地 `release/01.007.201`、build 19411；包内容从已安装游戏实际提取，并叠加其他工具的普通 triad 补丁。

## 合并到会加载的包

1. 在“额外预载”按名称／哈希选包，或在“包目录”开启“选为额外预载包”。支持全选、选择搜索框匹配结果、已知名称的虫族／机器人／光能者筛选。
2. 保持“应用包清单合并”开启。默认目标为 `packages/content/global_resources`；也可添加环境共享包、任务包等目标。目标可在目录中勾选，或在额外预载页按路径／哈希增删。
3. 点击“生成并预览依赖展开”。程序递归展开 package 描述符，合并实际叶资源，按类型与名称去重，保留目标原有资源。循环描述符图按已访问集合处理。
4. 关闭游戏，点击原有“写入游戏”。生成独立 `.patch_N`；原始 NXA 容器保持原样。资源随目标包被游戏实际加载的流程读取。

此方式不依赖其他玩家入房，也不会仅向 boot 添加已有的 package 描述符后就宣称已加载。

## 追加环境／星系包数组

1. 先选好额外包。
2. 在“环境／星球”打开目标配置，点击“向包数组追加选中包”，或逐项输入包路径／哈希。
3. 在“额外预载”关闭“应用包清单合并”，可只写数组修改；也可同时使用两条路线。
4. 点击“写入游戏”。原数组为空也可扩容：在原 LDLD 块末尾追加数据，重建指针和项数，保持其他偏移有效，再生成保持原哈希的认证文件。

数组已有项可修改；输入 `-` 删除。指针、项数和来源块由程序维护。

## 编辑包内容

“全局／任务”和“包目录”提供实际清单新增、替换、删除。

- 输入格式：`类型 名称或哈希`，例如 `texture 0x0123456789ABCDEF` 或 `unit content/example/example`。
- 已有条目输入 `-` 删除；“追加资源”用于新增。
- 每组 50 项，使用“上一组／下一组”访问全部内容。
- 统计自动重算。哈希、归档位置等身份元数据用于定位资源，不是加载开关。
- 通过底部“预设 → 预载方案”保存和载入命名方案，支持重置；旧 1–5 预设自动导入新库。额外预载页仍可导出和导入设置目录的 `preload-export.json`。

装备、敌人和环境标量组件继续使用原有编辑流程。清单及可扩容数组保存在 `preload_config.json`。

## 现有 mod 与恢复

包内容由编辑器自带的归档读取层（`offline/archives.lua`）直接从包所在的游戏归档读出 `.package.main`，不再需要 Filediver；之后使用按游戏和第三方补丁状态区分的缓存。

归档读取只读游戏原归档、不含 `.patch_N` 覆盖，因此本模块另行解析普通补丁并按编号叠加。若编辑后第三方又修改了该包，显式清单覆盖会拒绝写出。

包补丁与实体 Unit 别名补丁按源归档合并；保留 Unit、GPU、stream，并补齐所需别名依赖。安装使用现有事务、所有权记录和失败回滚。恢复游戏原文件时移除本编辑器拥有的补丁，保留其他 mod；保存的预载配置仍可下次使用。

全选没有人为的 64 包上限，文件生成支持完整目录。实际可驻留数量取决于游戏加载系统和内存，需要游戏内验证。

## 验证范围

已验证真实包增删改及无变化往返；沙漠叶资源追加到冰原共享包、保留原资源并去重；3,632 个包的有限闭包（约 14.7 万叶资源，数量受其他 mod 影响）；空环境数组扩容及认证回读；其他 mod 合并；Unit/GPU/stream 保留；安装恢复事务；中英文界面、文本输入、筛选、预设和重置。

这是文件和编辑器层验证。**尚未在游戏内确认新增数组是否被运行时消费，也未确认全局／任务包合并的实际驻留效果和容量。** 生成状态不会显示成“游戏已加载”。

热加入页保留协议解析参考。修改协议描述符不等于执行加载请求；本功能不调用 RPC，也不修改游戏可执行代码。原生主动加载是后续验证路线，没有伪装成已实现按钮。
